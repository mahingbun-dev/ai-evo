# M5「版本化、定时评测与报告外发」收尾记录（2026-10-23）

M5 把平台从「活数据即事实」升级为「版本可锁定、评测可定时、报告可外发」，
落地四块：数据集版本化（打版/行级 diff/恢复 + 任务锁定版本运行）、评测
模板版本化（打版/字段级 diff/恢复 + A/B 模板版本对照的任务化实验）、
定时评测（task_schedules cron 调度 + 周报聚合归档推送）、报告外发
（share_links 免登录只读报告 + 限流/无差别 404 枚举防护）。四个工作项
QE5-1 ~ QE5-4 依次落地，本文件为 M5 验收要求的里程碑收尾 sync-log。

## 三、评审结论

评审通过。复述核对：M5 落地了四块能力且均为真实现（无桩代码）：
(1) 数据集版本化——dataset_versions 表复用 dataset_snapshot 快照
（task_id 放开可空），打版/列表/行级 diff（稳定行键对齐、超500行截断）
/恢复（软删重写），任务可绑「跟随最新(NULL，存量行为不变)/锁定版本」，
锁定执行走版本快照加载，换数据集不切版本号会被 400 拒绝；(2) 模板
版本化——template_versions 表（content JSON 十字段全量快照+版本号唯一
约束），手动打版/列表/字段级 diff/恢复（恢复前活内容自动留存进版本
链），编辑接口携带 version_changelog 即改前自动打版；A/B 模板版本对照
为任务化实验——复用 ab_test_sessions（mode=template 七列、model_a/b_id
放开非空），从源任务复制两个变体任务（create_task 全量校验、模板派生
字段取版本 content 覆盖），变体运行走既有任务 run 端点，对照状态与
均分读取时从变体任务最新执行记录推导；(3) 定时评测——task_schedules
（一任务一条、window 时段限制、next_run_at CAS 认领）+ 自实现 vixie
子集 cron（不引 croniter、一年内无触发拒绝），api 进程 lifespan 60s
扫描（Redis 锁+CAS 双保险单写），投递走既有 run 入口语义（互斥/配额/
priority=NORMAL，提交拒绝 fail_task 落失败态）；周报 weekly_reports
周一 08:00 幂等聚合（覆盖度/提效/门禁通过率）markdown 归档，webhook
新事件+SMTP 可选推送，停机后首拍补生成；(4) 报告外发——share_links
（token 只存 sha256、明文仅创建返回一次，sh_+24 字节 urlsafe=192bit
熵），免登录公开端点先限流（429）后无差别 404（不存在/吊销/过期同码
同体），管理面创建/列表/吊销挂 RBAC+归属+审计，公开访问落 VIEW 审计；
前端 /share/:token 免登录只读页按 Results 同一数据口径重写，Results
分享弹窗含报告版本/有效期/范围/吊销管理。（来源：主线交接的独立评审

## 四、遗留事项（评审逐条核对确认，来源：主线交接材料）

### QE5-1

1. 打版对比入口做了简化取舍：方案原文只提「diff 视图双栏」，未规定
   from/to 任意组合选择器；本实现提供列表行「与最新版对比」一键入口
   （最新版行点击给提示），任意两版本对比可经 API
   （GET .../versions/diff?from=&to=）使用——若评审要求前端任意组合
   选择，可在抽屉补两个下拉，属小改动。
2. 恢复操作不自动为恢复前状态打版（方案未要求），改为恢复前二次确认
   弹窗明示「当前未打版的变更将丢失」并提示可先打版。
3. alembic 离线 --sql 模式在本仓库基线（改动前）即因既有迁移使用
   sa.inspect 而失败，非本次引入；在线升级已在真 PG 全链验证通过。

### QE5-2

1. 「模板编辑自动或手动打版」实现为「携带即自动」：编辑接口新增可选
   version_changelog 字段，携带（非 None）即先把改前内容打版再应用
   编辑；不携带则不打版（避免每次保存都膨胀版本链）。前端在编辑弹窗
   提供「版本说明」输入承载该意图。
2. A/B 模板版本对照未做后端 auto_run：变体任务的运行由前端「运行 A /
   运行 B」按钮走既有任务 run 端点（RBAC/配额/互斥全口径），避免后端
   绕过任务执行权限链路；对照状态与均分在读取时从变体任务最新执行
   记录推导（不落库）。
