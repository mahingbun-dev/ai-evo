# M6「License 与治理墙」收尾记录（2026-10-23）

M6 把平台从「功能全开源」升级为「企业能力靠 license 授权、用量可对账」，

计量漏斗 + 月度运行数/团队聚合 + license 规模对账 + 超额只告警不阻断）。
三个工作项 QE6-1 ~ QE6-3 依次落地，本文件为 M6 验收要求的里程碑收尾

### 用量计量（QE6-3）

- `app/services/model_caller.py`（+109 行）：进程内计量收集器——
  `_USAGE_LOCK` 线程锁 + `_USAGE_ACCUMULATOR`（模型→{prompt/
  completion/total_tokens} 累计）；`record_usage` / `record_usage_totals`
  （只有总量时拆分维度记 0）/ `reset_usage_tracking`（任务开始清零）/
  `collect_usage`（收割深拷贝）；`_extract_usage` 从响应 raw.usage
  尽力提取（OpenAI 兼容 prompt/completion/total 与 Anthropic
  input/output 两形态统一，无 usage 不猜值不记）；`_meter_call_result`
  在 `call()`（异步）与 `ModelCallerSync`（同步）漏斗收口——成功调用
  计量入收集器并把 usage 附到返回值供未来行级归因（不改变既有
  success/content/raw 契约）。进程模型：celery worker prefork 一子进程
  同时一任务，executor 线程池行级并发共享收集器锁保护累加，计量不丢行
  （不逐调用落库——行级并发下写入量不可控）；api 进程不经评测链路
  收集器恒空。
- `app/services/plugin_evaluator.py`：Claude Code 裁判走 SDK 子进程
  不过 model_caller 漏斗，在 `_cc_query` 的 usage_sink 处就地
  `record_usage_totals` 喂入（只有 total，拆分维度记 0），与被测/
  传统裁判调用同池、任务收尾统一收割。
- `app/services/evaluation_task_service.py`：`_attach_model_usage`
  终态收割写 `task_execution_records.model_usage`——complete/fail/stop
  三终态路径全挂（失败/停止的运行同样消耗用量），计量异常只 warning
  不影响收尾主流程；api 进程收集器恒空自然落 NULL。
- `app/tasks/evaluation_tasks_async.py`：任务开始
  `reset_usage_tracking` 清零 + `check_run_overage` 月度运行数超额
  对账（只告警不阻断，检查异常在 usage_service 内吞掉）。
- alembic 迁移 `d8f2b6c4a9e1_add_model_usage_column.py`：
  task_execution_records 增可空 JSON 列 `model_usage`

- `app/services/usage_service.py`（248 行）：

## 三、评审结论（来源：主线交接的独立评审结论）

评审通过。复述核对：M6「License 与治理墙」落地了三层：

(1) Ed25519 离线 license 体系——超管 POST /admin/license 上传（验签
前置、坏文件 400 不落库、64KB 上限、落审计只存概要）与 GET
/admin/license/status 状态查询，api 启动 lifespan 加载 DB 最新一行
验签并进程内缓存，无/过期/验签失败一律降级 oss 并多行横幅告警（交接
原文至此截断）；(2) 企业功能位治理——entitlements 门面统一判定，
审计导出授权闸由 AUDIT_EXPORT_ENABLED 环境位移交 license 功能位
audit_export（未授权 403+upgrade_required、环境位降级为紧急停止总闸），
免登录分享报告页白标/水印由服务端 branding 内嵌判定，前端据
/auth/status 附带 license 块渲染企业功能锁标；(3) 用量计量——被测与
裁判 API 调用统一过 model_caller 漏斗、CC 裁判 usage_sink 就近喂入，
任务开始 reset/终态收割写执行记录 model_usage，月度运行数与团队 token
经 GET /admin/usage/summary 聚合供 license 续约对账，超额只告警不阻断。
（(2)(3) 复述按交接材料 QE6-2/QE6-3 段与同一评审口径对照未提交改动
核对补全；(1) 为交接原文。）评审逐条核对确认的口径偏离 / 自行定义 /

## 四、遗留事项（评审逐条核对确认，来源：主线交接材料）

### QE6-1

1. 方案「license 状态表（或 settings 行）」二选一，落地为独立表
   platform_licenses（存原文+sha256 指纹做证据链，不存验签结论），

3. 生产密钥不入库靠纪律+文档+keygen 仓库内告警把关（未加 gitignore
   硬拦，避免误伤测试密钥）。

### QE6-2

1. 审计导出语义升级：M4 的 AUDIT_EXPORT_ENABLED（默认关、未开 404）
   按方案 M6「审计导出进企业位」改为 license 功能位 audit_export 授权

2. 报告白标/水印接线在免登录分享报告页（方案 M0 行指定面）：branding

   免登录页不暴露 /auth/status；开源版显示品牌页脚+右下角水印，授权
   对应位后隐藏。
3. require_feature 返回裸依赖函数（调用方包 Depends），与仓库
   require_scope 工厂风格一致，而非方案字面未指定的 Depends 嵌套形态。

### QE6-3

1. 计量采集用「进程内收集器 + 任务开始 reset/终态收割」而非逐调用落库

   拆分维度记 0）——即「泛化到所有裁判与被测调用」对 CC 裁判是就近
   喂入而非过漏斗。
3. 汇总为纯后端 API（方案未要求前端页面）；超额告警邮件复用周报 SMTP
   凭据、新增 USAGE_ALERT_EMAIL_TO 收件人。
4. 测试修复：本机共享 Redis 会跨测试累计 API Key 认证失败节流
   （ip+prefix 5 次/10 分钟锁 15 分钟）把 401 变 429，三个相关测试
   文件替节流器为 no-op 保证确定性（CI 无 Redis 本就 fail-open 不受
   影响）——属测试隔离修复非绕过。
