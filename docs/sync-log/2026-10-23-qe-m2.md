# M2「方法论补课」收尾记录（2026-10-23）

M2（QE2-1 ~ QE2-4）补齐方法论四件套：终态校验器（模型调用/被测 agent
执行之后的确定性断言，先于且独立于裁判）、agent 轨迹匹配（会话工具调用
序列四模式确定性断言）、pass^k 与 A/B 显著性统计（τ-bench 口径
pass@1/pass^k + Wilcoxon/McNemar 配对检验）、裁判治理（配置快照可追溯 +
输入消毒开关 + 金丝雀空样本对抗探针）。本文件为 M2 验收要求的里程碑收尾
sync-log。

### QE2-3 pass^k 与 A/B 显著性

- `app/services/pass_k.py`：pass@1（k 次 trial 通过数的均值）与 pass^k
  （k 次全过的行占比）双口径，trials 2-5（1=关闭，行为与旧版一致）；
  judge 类型 evaluation_tasks.trials 行内跑 k 次「模型调用+裁判+校验」
  合并为一行；success_rate / consistency / latency 复用各自既有
  repeat_count 通道同口径聚合；分数标准差/标准误（n-1 分母）。
- `app/services/ab_statistics.py`：连续值配对 Wilcoxon 符号秩（主检验）+
  配对 t + Cliff's delta 效应量 + 均值差 95% CI；比例配对 McNemar 精确
  检验；输出统一 `{p_value, conclusion, n, adequate}`（样本量充足提示）。
- `app/api/ab_test_api.py` / `app/services/ab_test_service.py`：A/B 多轮
  （同输入逐轮并行 A/B，轮数 1-10）+ 逐轮明细合并 + significance 随会话
  落库；前端 ABTest.vue 轮数配置与显著性面板（耗时/成败双结论）。
- `requirements.txt`：`scipy==1.18.0` 增直依赖钉版（与 requirements.lock
  一致，此前经 ragas 传递引入，无需重编 lock）。
- 新增 `tests/unit/test_pass_k.py`、`test_consistency_pass_k.py`、

## 四、遗留事项（评审逐条核对确认，来源：主线交接材料）

### QE2-1

1. file_assert/http_assert 的 jsonpath 为极简点路径子集（a.b[0].c，不支持
   过滤器/通配符），代码与 user_guide 均已注明——方案只写「JSONPath 断言」
   未定完备度，避免引入新依赖。
2. http_assert「走 egress 白名单」实现为 worker 侧复用 webhook_url_guard
   的解析后 SSRF 守卫（默认仅公网、DNS 重绑定拒绝、config.allow_private
   显式放行且任务配置可审计），而非把原生断言放进沙箱容器的 egress 网络
   档——沙箱通道保留给 script 类型。
3. script 校验器 v1 的 stdin 携带模型输出/会话摘要/params（满足方案「输入
   含模型输出与会话 trace」），未暴露 input_mapping 配置面。
4. README.zh-CN.md 首段仍停留在「M1 未落地」的过期口径（M1 交付时漏更），
   本次一并修正并补 M2 校验器口径。

### QE2-2

1. 方案只给了四个模式名未定义语义，本实现按「顺序敏感 × 期望须全出现 ×
   额外调用容忍」三维矩阵自行定义（strict=序+全现+不容忍额外，unordered=
   计数制+容忍额外，subset=按序子序列+容忍额外，superset=仅禁止额外、
   missing 恒空；forbidden 任何模式命中即失败），语义表已写入用户指南。
2. 「Results 轨迹 Tab」落地为 Results.vue 的「轨迹匹配」区块而非独立
   el-tabs 标签页——现状 Results 页本无标签页结构，且与 QE2-1 终态校验区
   保持同构（每行抽屉内按需展开，含判定卡+统计 chips+缺失/禁用/未期望
   清单+el-timeline 时间线）。
3. 轨迹来源限定为数据行 session_messages（结构化 SessionRecord）——hub
   执行包内的 claude_thread 包（plugin_eval_trace.py:33 保留的原始 jsonl）
   需经会话文件导入生成 session_messages 后才可断言，markdown 文本型会话
   记 status=error。
4. 轨迹不通过不阻断该行评测和裁判打分（区别于校验器 FAIL 可中断）——
   「截断 trace 虚高」的拦截路径是 trajectory_match_rate 挂门禁，与方案
   「可作门禁 metric」定位一致。

### QE2-3

1. 显著性配对数据源：当前 A/B 页为单次"Hello"快速测连，本次加多轮（同
   输入逐轮并行 A/B）后配对项为逐轮耗时（Wilcoxon/t/Cliff's δ，
   lower-is-better）与逐轮成败（McNemar）——方案未定义配对指标，未接入
   裁判逐轮评分（需裁判参与的任务级 A/B 留待后续）。
2. A/B 多轮上限取 1-10（方案只给任务 trials 2-5，A/B 轮数无规定，按显著
   性建议样本量量级取 10）。
3. judge trial「通过」判定方案未定义：配置终态校验器时以 verification
   status==pass 为准（对齐 M2 验收「校验器+pass^k 全链路」），未配置时
   退化为「trial 产出有效裁判分」，已在代码注释与用户指南声明。
4. 多 trial 合并行除 average_score（k 次均值）外的证据字段（维度分/
   反馈/校验证据）取首个成功 trial，完整 trial 明细单列 trials_detail——
   多次 trial 全量证据入库会膨胀 row_result。
5. pass^k 未接门禁 metric（方案 2.3 未要求，M6 仿真节才要求）。
6. 离线快照检查 pre-existing FAIL：.offline-snapshot.json（末次 70776cf）
   落后于 requirements.lock（末次 0dd663f，早于本次工作，两文件工作区均
   无改动）——修复需开发机跑 tools/prepare-offline.sh + 上传 token，超出
   本项范围；scipy==1.18.0 已在 lock（经 ragas 传递引入），本次仅在
   requirements.txt 增直依赖钉版（与 lock 一致，无需重编 lock，快照哈希
   不受影响）。

### QE2-4
