## 三、评审结论（来源：主线交接的独立评审结论）

评审通过。复述核对：M8「标注闭环与收尾」把方案 QE8-1~QE8-5 全量
落地：(1) 标注闭环——新 annotations 表（alembic b3e7c9f5d2a8，锚定
evaluation_results 行、一行一标幂等覆盖、级联删除），Results 页标注
模式弹窗（失败行/低分行优先队列+快捷键打金分+S 跳过），Statistics
新增裁判一致性 Tab（scipy Pearson/Spearman）。评审逐条核对确认的
口径偏离 / 自行定义 / 顺延说明（QE8-1 ~ QE8-5）如下：

### QE8-1

1. kappa 未用 sklearn（非仓库依赖，.venv 内无该包），按仓库风格纯实现
   并配手算对拍用例；Pearson/Spearman 用已钉版的 scipy
   （requirements.txt:28 直依赖，.venv 验证可导入）。
2. 一致性报告端点随 stats 路由沿用既有 ensure_super_admin 门（与
   周报/概览同口径），方案未单独指定角色；Results 页标注入口对
   viewer 隐藏且后端 403（已测）。
3. 队列含已标注行（annotation 字段空=待标）而非只回待标行——前端
   跳转下一待标行，已标行可回看修正，与「一行一条幂等覆盖」口径
   配套。
4. README「能力表总刷新」按方案留给 M8 收尾项，本次只在结果分析行
   追加标注闭环事实口径。

### QE8-2

1. 对拍为同步端点（样本上限 10、默认 5，两引擎每行并发、行间串行），
   未做异步任务化——方案未指定形态，诊断工具场景下同步最简；超大批量
   对拍属后续演进。
2. DSH 裁判的会话内容采用内联（上限 15 万字符截断并标注）而非 CC 式
   落盘+Read 阅读：DSH 普通轮次无 CC 式文件阅读协议保证，边界已写进
   user_guide 裁判引擎节（超长会话建议 CC 引擎）。
3. 对拍报告不落库（实时生成返回），与「标注一致性报告」不同——后者
   有人工标注数据底座可回看，对拍是即时诊断物；如需归档可后续挂导出。
4. 未跑全量测试（按要求定向）：新增 19 项全绿 + 周边既有套件 164 项
   回归全绿；pnpm -C frontend run build 通过。

### QE8-3

1. runtime 字段采用无条件携带（含缺省 runc）而非「仅 runsc 时携带」
   ——与 net_profile 字段同风格，executor 侧缺省同值行为等价不变，
   且避免「字段缺失=档位不可知」的歧义；对应更新了 test_sandbox_driver
   的白名单字段集断言。
2. .env.example 新增注释项 SANDBOX_RUNTIME（方案未点名，但 gvisor
   文档配置入口此前在 .env.example 无暴露，属收口顺手补齐，默认注释
   不启用）。
3. 实机 runsc 档沙箱逃逸集复跑（sandbox_e2e 档）仍属部署机显式执行项，
   本项单测范围内不触及（与既有口径一致）。未跑全量测试（按要求定向）：
   本项相关 5 个套件 342 项全绿。

### QE8-4

1. 端点仅支持 JSON body 推送（OTLP/HTTP JSON 为方案主形态）；
   Phoenix/Langfuse 走「导出 JSON 直接 POST」而非文件上传——文件上传
   通道既有 /import/sessions 已覆盖 Langfuse，不重复建面。
2. Phoenix 格式以官方 CLI 导出（traceId+spans+OpenInference 平铺属性，
   来源 arize.com/docs/phoenix retrieve-traces-via-cli）为准，另兼容
   旧 data 数组与裸 span 形态；未实测真实 Phoenix 实例（无环境），以
   文档格式构造用例。
3. OTLP 消息提取按 OTel GenAI 语义约定（gen_ai.prompt/completion）
   +OpenInference（input/output.value、llm.*_messages）双口径，未覆盖
   全部 GenAI 新式分片键（gen_ai.prompt.0.content 等）——最小实现边界，
   未覆盖形态落入工具 span 分支不会报错。
4. test_hub_import_api.py 存在 11 项既有失败（在干净 HEAD f13e298 上
   复现相同失败，与本项无关，未触碰）。未跑全量测试（按要求定向）。

### QE8-5

1. 「9 种」计数口径：按可建任务的 9 种类型（judge/agent/consistency/
   success_rate/rag/binary_classification/latency/plugin/safety，
   safety 如实描述）表述，persona 仿真（经场景运行、不建任务）单独
   描述——前端 Simulation.vue 既有「第 9 种评测类型」文案属 M7 出厂

2. user_guide 重排为增量式：总览图/类型表更新、补仿真评测章节与目录、
   TOC 覆盖核对（脚本验证 14 个功能小节全在目录）；未做全文重写，
   评测类型详解未为响应耗时/插件补写详解章节（总览表已覆盖，既有缺口
   非本里程碑引入）。
3. M8 sync-log 已落盘改动内容/遗留事项/入库范围，但门槛结果/评审结论
   两节留「待主线验收后回填」占位——按 M1-M7 惯例该两节由验收与评审
